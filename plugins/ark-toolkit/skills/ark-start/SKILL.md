# ark-start

> **通用性原則**：本 plugin 是通用工具，會發佈給其他使用者。個人化內容
> （帳戶設定、排程參數、專案協定、一次性調整）放執行資料夾 `~/.ark-toolkit/`
> 或專案自己的 `docs/`，**不要直接改 plugin**；只有通用的修復與功能
> （附測試）才動 plugin 本身。

初次上手的驗證軌。把「**初次測試驗證**」與「**實際串接看單**」明確分成兩步：

1. **模擬單驗證**（`verify.py`）—— 模擬環境送單並撤單，證明這台機器的
   委託路徑通（金鑰、網路、下單參數組合）。寫死 simulation，**碰不到真錢**。
2. **實際串接看單**（`ark-read`）—— 正式環境查詢帳上持倉，證明真實資料讀得到。

第 1 步通過後**自動串接**第 2 步，不需使用者再下指令。

## 執行環境（uv）

所有指令以 `uv run` 執行：依賴宣告在腳本開頭（PEP 723），uv 會自動準備 Python 與套件。
執行前先確認 uv 存在，沒有就直接安裝後繼續（不必詢問使用者）：

```bash
command -v uv >/dev/null || brew install uv || curl -LsSf https://astral.sh/uv/install.sh | sh
```

## 流程（對 Agent 的執行指引）

```bash
uv run skills/ark-setup/setup.py --show      # 0. 先確認帳戶設定狀態
uv run skills/ark-start/verify.py            # 1. 模擬單驗證（送單即撤，不成交）
uv run skills/ark-read/read.py               # 2. 驗證通過後自動接著跑（實際串接）
```

依步驟 0 的結果分流：

| 設定狀態 | 行為 |
|---|---|
| 尚未設定（`SetupRequired`） | **先執行 ark-setup skill** 完成帳戶設定，再回來繼續步驟 1 |
| 有券商 API 帳戶 | 步驟 1 → 通過 → **直接接著執行步驟 2，不要停下來等指令** |
| 只有檔案帳戶（無 API） | 模擬單不適用（沒有可送單的 API），直接跳到步驟 2 |
| 純 ARK 模式（空清單） | 本 skill 不適用——沒有真實帳戶可驗，告知使用者即可 |

**自動串接是本 skill 的一部分，不是新任務**：`verify.py` 以 exit 0 結束時，
不要總結報告後停下，直接執行 `ark-read` 並把帳上持倉唸給使用者，
這樣使用者一次就看到「委託路徑通了＋真實資料讀得到」的完整證據。

## 判讀

- `verify.py` 印出 `✅ 整合驗證通過` 且 exit 0：整股與零股兩種委託都送得出去、撤得掉
- 登入失敗：金鑰問題 → 引導跑 ark-setup 更新金鑰
- 送單被拒：訊息裡有交易所回覆，多為模擬環境暫停服務（非交易時段常見）——
  說明原因並建議交易日再驗，**不要**改用正式環境重試
- 驗證用 0050 掛跌停 1,500 股（整股＋零股各一腿），不會成交，送完立即撤單

## 與其他 skill 的關係

- `ark-setup` 負責**帳戶設定與憑證**（含正式環境測試登入）；本 skill 負責
  **委託路徑驗證與串接確認**——設定歸設定，驗證歸驗證
- `ark-agent` 上線（切 live）前，先跑本 skill 確認委託路徑
- 驗證腳本依賴 `ark-agent/execute.py` 的下單層（`build_legs`／`place_legs`），
  驗的就是每日決策軌實際使用的那條路徑
