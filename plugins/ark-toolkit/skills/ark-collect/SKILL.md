# ark-collect

> **通用性原則**：本 plugin 是通用工具，會發佈給其他使用者。個人化內容
> （帳戶設定、排程參數、專案協定、一次性調整）放執行資料夾 `~/.ark-toolkit/`
> 或專案自己的 `docs/`，**不要直接改 plugin**；只有通用的修復與功能
> （附測試）才動 plugin 本身。

收集 `ark-setup` 設定的**每個帳戶**的持倉，stdout 印出各帳戶明細與合併結果
（股數相加、均價加權平均），原生視窗按「確認」後寫入 `~/.ark-toolkit/staging.json`。
之後 `ark-sync` 只吃這份快照——**你確認過的就是實際套用的**。

帳戶清單只有永豐（無檔案帳戶）時不必跑本 skill：`ark-sync` 會直接即時讀取。

## 執行前必須確認

1. 已執行 `ark-setup` 設定帳戶清單
2. 執行時會彈原生視窗（確認、選檔），請提醒使用者留意畫面（可能被其他視窗遮住），
   Bash 逾時設長（建議 10 分鐘）

## 執行環境（uv）

所有指令以 `uv run` 執行：依賴宣告在腳本開頭（PEP 723），uv 會自動準備 Python 與套件。
執行前先確認 uv 存在，沒有就直接安裝後繼續（不必詢問使用者）：

```bash
command -v uv >/dev/null || brew install uv || curl -LsSf https://astral.sh/uv/install.sh | sh
```

## 用法

```bash
uv run skills/ark-collect/collect.py
```

流程：（第一次）問 ARK 均價口徑 → 讀永豐（API，套用口徑）→ 逐一讀檔案帳戶 →
印明細 → 視窗確認 → 寫快照。按「取消」就不寫，什麼都不留。

**均價口徑在這一步定案**：多帳戶時 `ark-sync` 只讀快照、不重讀來源，所以永豐的
含息／手續費換算必須在 collect 讀取時就套用（1.3.0 漏了，快照永遠是券商原值，
1.3.1 修正）。config 還沒有 `cost_basis` 時這裡會開視窗問一次、之後沿用；
口徑的意義見 ark-sync 的「均價口徑」一節。檔案帳戶只有一欄均價，口徑對它無效。

## 檔案帳戶的救援機制

券商匯出檔每次檔名都不同（多半落在 ~/Downloads），所以：

- **配置路徑找不到檔案** → 跳原生選檔視窗當場指定
- **檔案不是今天匯出的** → 詢問「重新選檔／直接使用」
- **新檔表頭對不上欄位** → 詢問後重新對應欄位

當場指定的新路徑與欄位對應會寫回 config，下次直接生效。

## 快照的三道防線

1. **僅當日有效**——`ark-sync` 讀到跨日快照一律拒絕，要求重收（不提供 override，
   重收很便宜，套用舊資料很貴）
2. **任一帳戶 0 檔拒寫**——0 檔多半是讀取失敗，寫進快照會在 sync 變成
   「刪光該帳戶持股」的計畫（與 `sync_is_safe` 防同一類事，守在更上游）
3. **絕不部分合併**——任一帳戶讀不到即整體失敗並指名帳戶

## 與其他 skill 的關係

- 階段二是 `ark-sync`：讀快照對 ARK 執行（建議先 `--dry-run`）
- 只想看資料不同步 → 用 `ark-read`（不寫快照、不彈視窗）
- 帳戶清單管理 → `ark-setup`
